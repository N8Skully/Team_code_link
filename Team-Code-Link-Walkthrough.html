Team Code Link

A full walkthrough for people who have not set this up before. Read it from the top. Do the steps in order. One person is the host. Every other person follows the join steps on their own computer.

When you are done, up to six Windows computers can see one shared project folder, sit in one private room, and each start a Cursor agent that can hear that room.

1. The words this guide uses

These words show up on the screen. Here is what each one means in this program.

WordWhat it means
ComputerOne physical PC. In the room it has a short name you choose, such as nate or office. That name is the seat.
AgentA program that writes code. This guide uses Cursor’s agent. It is a separate program from the chat window already open in Cursor. Connecting puts that program into the room. It does not attach the chat you are reading right now.
RoomA private list of who is here, what they said, and which part of the work they are on. It runs on the host computer. It is not a website on the public internet.
Room codeEight letters and numbers, such as AB12CD34. It is the password for this room. The host reads it from the top of the window and sends it to the other people. It is not a web address.
TailscaleA program that gives each computer a private address starting with 100. and lets those computers find each other. The project is not shared with the public internet. Only computers you invited can see it.
TailnetThe private network Tailscale makes for one account. Every computer in this guide must be signed into that same tailnet. Two people with two unrelated Tailscale accounts cannot see each other.
HostThe one computer that starts the room and shares the project folder. Leave its Team Code Link window open the whole time.
JoinWhat every other computer does. It uses the room code to find the host over Tailscale and enter the room.
ProjectThe piece of software you are building together. It has a short name, such as Shared, and it lives in one ordinary Windows folder.
SourceThe one computer whose folder is the real copy of the project. Everyone else opens that folder. Only one computer is the source at a time.
Share pathThe address of that folder, written like \\office\Shared. The word before the second slash is the host computer. The last word is the project name. If the computer has no usable name, the address uses the 100. number instead, like \\100.125.156.83\Shared.
ConductorThe person in charge of the room. The host becomes the conductor when they click Host and share. The conductor can hear every part and can send instructions once a plan exists.
PartOne piece of the job, such as “the canvas” or “the toolbar.” A plan is the list of parts. The window does not have a button that creates that list yet. Section 9 explains how a plan gets published.
SkillA named ability already installed on that computer, read from a file called SKILL.md. The agent brings the checked skills into the room. You do not type skill names by hand.

2. What you need on every computer

  • Windows.
  • The program file Team Code Link.exe. It is already built. Section 4 says where it is and how the other computers get that same file. Downloading the GitHub repository does not include this file.
  • Tailscale, installed and signed into the same tailnet. Section 3.
  • Cursor, installed and signed in, on every computer that will run an agent. The Connect button starts Cursor’s agent program. If that program is missing, the room can still list the computer, but no agent is actually running.
  • Python installed so that the command python3 works. This is what stops two Cursor agents from saving the same file at the same time. Open PowerShell and type python3 --version. If Windows says it cannot find the command, install Python from python.org/downloads/windows, and on the first installer screen turn on “Add python.exe to PATH.” After it finishes, copy python.exe to a file named python3.exe in that same folder so the command name is python3.

The host computer has one extra requirement. The person who clicks Host and share must start the program with Windows administrator rights. Section 6 explains the exact clicks. The other computers do not need administrator rights just to join.

3. Put every computer on the same Tailscale network

Do this on the host first, then on every other computer. Tailscale is the private wire. Team Code Link does not replace it.

  1. On the host, open a browser and go to https://tailscale.com/download/windows. Download the Windows installer and run it. Approve the Windows prompts.
  2. When Tailscale asks you to sign in, create an account or sign in. This account owns the tailnet. A tailnet is the private list of computers that are allowed to see each other.
  3. After sign-in, click the Tailscale icon near the clock. It should say Connected. That computer now has a private address that starts with 100.
  4. Invite the other people. In a browser, open https://login.tailscale.com/admin/users. Invite each person by email. They must accept the invite. Signing up for their own separate Tailscale account, and never accepting this invite, leaves them on a different tailnet. Those computers cannot see the host.
  5. On each other computer, install Tailscale the same way. Sign in with the invited account. The Tailscale icon should say Connected.
  6. On the host, open the Tailscale icon and look at the list of machines. Every computer that will join must appear there. If a computer is missing, it is not on this tailnet yet. Stop and fix the invite before you open Team Code Link.

You should see each computer in the Tailscale machine list, and each one should show Connected. You do not turn on an exit node, a subnet router, or a public funnel. Those are other Tailscale features. This setup does not use them.

4. Get Team Code Link.exe onto every computer

The program is one file, and it is already built on the host computer. You do not clone the repository and build it to start. GitHub has the source code. GitHub does not have this program file. A download of the repository is the text of the program, not the program you double-click.

On the host, the file is:

F:\Portal9\Team Code Link\Team_code_link\dist\Team Code Link.exe

The source that matches this file is on main at https://github.com/N8Skully/Team_code_link. The same work is also on the fork https://github.com/N8Skully/Team_code_link-source, branch switchable-source. An older release named v0.1.0 on that fork is an earlier program. Do not use it for these steps.

  1. On the host, open File Explorer and go to F:\Portal9\Team Code Link\Team_code_link\dist. The file inside is Team Code Link.exe.
  2. Copy that file to each other computer. Use a USB drive, email, or any file transfer you already have. Each person saves it somewhere they can find, such as the Desktop. They do not build it.
  3. On the host, when you are ready to share the project, start this same exe. Right-click it and choose Run as administrator, as section 6 describes. A normal double-click is enough on a computer that is only joining.

Keep two folders separate. F:\Portal9\Team Code Link\Team_code_link is where the program was built. The project folder you choose in section 6 is the work everyone shares. Do not pick the Team Code Link folder as the project folder.

5. Learn the window before you click Host

Double-click Team Code Link.exe. A single window opens. It does not open your web browser. The top bar is always visible. Read it from left to right:

ItemMeaning
Tailscaleconnected plus a 100. address means this computer is on the private network. not connected means Tailscale is installed but signed out, or it is not installed. This line is only about Tailscale. It does not mean the agent has joined the room.
CodeThe room code, or a dash before anyone hosts. After the host succeeds, this is the eight characters the other people type.
Agentnot connected until Connect or Host and share actually starts the agent program. A name such as nate/cursor means that seat is in the room. The Agent tab says whether the Cursor program itself is running.
Sourcenone until the host publishes the folder. After that, this is the \\computer\Project path.

There are five tabs:

  • Connection. Tailscale, host or join, the project, and the folder.
  • Agent. Start the Cursor agent for this computer.
  • Settings. The saved names and folder. Save stores them. It does not join the room.
  • Skills. Checkboxes for abilities already on this computer. Uncheck any this agent should not bring.
  • Live. Who is in the room, what they said, and, after a plan exists, the conductor’s instruction boxes.

6. On the host: start the room and share the folder

Do this on one computer only. Close the window if you already opened it without administrator rights, then start it the way step 1 says.

  1. Right-click Team Code Link.exe. Click Run as administrator. Windows asks “Do you want to allow this app to make changes?” Click Yes. Administrator rights are required because Windows will not let a normal program create a shared folder for other computers. If you skip this, the room can still start, and a red line under the button will say to run as administrator. Source stays none until the share succeeds.
  2. Look at the top bar. It must say Tailscale connected and show a 100. address. If it says Tailscale is not installed, go back to section 3. If it says not connected, click Sign in with Tailscale and finish the login Tailscale opens. Wait until the bar says connected.
  3. Open the Connection tab. Set This computer to Host the room. The button at the bottom then reads Host and share.
  4. Project. Leave Shared, or type a short name made of letters, numbers, and hyphens, such as ToolsProject. This name becomes the Windows share name. Spaces are not allowed.
  5. Computer. A short name for this PC in the room, such as nate. Lowercase letters, numbers, and hyphens. The box may already contain a suggestion. If the Windows computer name is the word UNKNOWN, the program uses computer instead. Capitals are turned into lowercase.
  6. Agent. Leave cursor if this computer will run Cursor’s agent. That word is the kind of agent, not the chat title.
  7. Project lives. This chooses how the files arrive. On this computer, shared with Tailscale means the folder you pick in the next step is the real copy, and other computers open it over Tailscale. In a GitHub repo, copied into a folder here means the files start on GitHub and the program copies them into the folder once. Section 10 walks through both, including how to put one new file where the other person can open it. You can use both: GitHub holds a saved copy, and Tailscale is how the other computer opens the live folder.
  8. Folder on this computer. Click Choose folder. Pick a new empty folder, for example C:\Users\YourName\Documents\SharedProject. This is where the project files will live. Do not pick the Team Code Link program folder.
  9. Open the Skills tab. Checked rows are sent with this agent. Uncheck anything this agent should not claim. If the list says no SKILL.md files were found, this computer has no skill files in the usual Cursor, Claude, or Codex skill folders. You can still continue.
  10. Go back to Connection and click Host and share. Wait until the window answers. The first time can take a little while because it starts the room, joins this computer, starts the Cursor agent, and creates the Windows share.

Success looks like this on the top bar:

  • Tailscale connected, with a 100. address.
  • Code shows eight letters and numbers. Send those characters to the other people. Send the code itself, not a web link.
  • Agent shows a name such as nate/cursor. Open the Agent tab. It should say that name is running in the project folder. If it says the cursor program is not installed, Cursor’s agent program is missing on this computer. Install Cursor, sign in, and click Connect on the Agent tab again.
  • Source shows a path starting with \\.

A red line under the button is the reason it stopped. Read it. “Run Team Code Link as administrator” means close the window and do step 1 again. “No computer on Tailscale accepted that code” is a join error, not a host error. “The room did not start” means another Team Code Link window is already holding the room. Close the other one and click Host and share again.

If other computers cannot find the room

The room listens on port 8765. A port is a numbered door on the computer. Tailscale can be connected and Windows can still block that door. The program opens the file-sharing door (port 445) on the Tailscale adapter when the share succeeds. It does not open port 8765 for you.

On the host, open PowerShell with administrator rights: right-click PowerShell, then Run as administrator. Paste this and press Enter:

$adapter = (Get-NetAdapter | Where-Object { $_.InterfaceDescription -like '*Tailscale*' -or $_.Name -like '*Tailscale*' } | Select-Object -First 1).Name
New-NetFirewallRule -DisplayName "Team Code Link room" -Direction Inbound -Protocol TCP -LocalPort 8765 -Action Allow -InterfaceAlias $adapter

In plain language: find the Tailscale network adapter, and allow incoming room traffic only on that adapter. The public internet is not opened. Then try the join again from the other computer.

7. On every other computer: join the room

Each person does this on their own PC. They need Tailscale connected to the same tailnet, and a copy of Team Code Link.exe. They do not need administrator rights to join. They do need the room code from the host.

  1. Start Team Code Link.exe. The top bar must say Tailscale connected.
  2. On Connection, set This computer to Join a room. The button changes to Join. A Room code box appears.
  3. Type the eight characters the host sent. No https://, no spaces.
  4. Set Computer to a different short name from the host, such as office. Two computers must not use the same seat name.
  5. Set Agent to cursor if this computer will run Cursor.
  6. Folder on this computer can stay empty for a person who is only joining. The files they share are the host’s folder. The source path appears in the top bar after the join finds the host.
  7. Click Join.

Join works by asking every computer on the tailnet, on port 8765, whether it accepts that code. The host must still be running. If the message is “No computer on Tailscale accepted that code,” check three things: both Tailscale icons say Connected, both machines appear in the Tailscale machine list, and the host has allowed port 8765 as in section 6.

After a successful join, Code shows the same eight characters, Agent shows this computer’s seat, and Source shows the host’s \\ path. On the Live tab, both seats appear under Agents.

8. Connect the agent on each computer

A seat on the Live tab is only a name. The agent is connected when the Cursor agent program is running in the project folder.

  1. Install Cursor on that computer and sign in to Cursor at least once.
  2. In Team Code Link, open the Agent tab.
  3. Check Computer and Agent. Agent should be cursor.
  4. Click Connect.

Connect does four things. It puts this seat in the room. It writes the room tools into the project folder so that agent can talk to the room. It starts Cursor’s agent program in that folder. It tells that program to announce itself in the room and then listen.

The Agent tab should then say the seat is running in the project folder. The top bar shows that same name. When the program finishes its turn, the tab changes. It will say the seat is in the room and the agent program is not running. That is expected. The name remains. The coding program has exited. Click Connect again when you want another turn, or send that seat new instructions after a plan exists (section 9). A new turn starts for an instruction only when that seat is already on an active part.

Connect does not attach the Cursor chat that is already open. If the red line says the cursor program is not installed, Cursor’s agent program is not on this computer. Install Cursor, open it, sign in, and click Connect again.

9. Give the agents a plan

A plan is the list of parts and one sentence that says how those parts connect. Example: two parts named Canvas and Tools, and the sentence “The toolbar calls the canvas. The canvas is the only writer of the picture.”

The Team Code Link window does not have a button that creates this list. Hosting, joining, sharing the folder, and connecting an agent all work without a plan. The instruction boxes on the Live tab appear only after a plan exists, and only for the conductor.

To publish a plan, the host uses the project source and a small text file. On the host, create a file named plan.json in the project folder you chose in section 6. Put this in it, and change the titles to match the real work:

{
  "title": "Shared project",
  "framework": "Say, in one sentence, how the parts call each other.",
  "tasks": [
    { "title": "First part", "brief": "What this part is responsible for." },
    { "title": "Second part", "brief": "What this part is responsible for." }
  ]
}

title is the name of the whole job. framework is the one sentence everyone follows. Each item in tasks is one part. brief is the short description of that part.

The host window must already be open and hosting. In PowerShell, go to the project folder you chose in section 6, and point Python at workspace.py in the program’s source folder:

cd C:\Users\YourName\Documents\SharedProject
py -3 "F:\Portal9\Team Code Link\Team_code_link\scripts\workspace.py" plan --file plan.json

Change the first path to the real project folder. Leave the workspace.py path as it is on this host. If the command says this computer is not linked, Host and share has not been clicked for that project folder yet. If it says only the conductor can do that, this seat is not the conductor. The host becomes the conductor when Host and share succeeds.

After the plan is published, open Live on the host. Each part that is not finished has a text box. Write the detailed instructions for that part and click Send. Those words go to the room as that part’s approach. An agent on this computer that is assigned to that part can be started again with those words.

10. How to share a file

There are two ways a file moves between computers. Tailscale shares the live folder, so a file saved on the host shows up for the other person immediately. GitHub is a saved copy on the internet: you send a file up to GitHub, and the other person downloads that copy. Team Code Link can use either one. It does not use Tailscale’s separate “send a file” menu. The whole project folder is the share.

Use Tailscale when people are working at the same time and the host computer can stay on. Use GitHub when you want a copy that remains after the host is turned off, or when someone new needs the files without the host being awake. Many projects use both: work in the Tailscale folder, and send a snapshot to GitHub when you want a saved copy.

Share a file over Tailscale

Do sections 3 and 6 first. The host must be running Team Code Link as administrator, Tailscale must say connected on both computers, and the top bar on the host must show a source path that starts with \\.

A share path has two parts. In \\office\Shared, office is the host computer and Shared is the project name you typed. If the path uses a number, such as \\100.125.156.83\Shared, that number is the host’s Tailscale address. Either form is the door to the same folder.

  1. On the host, open the folder you chose with Choose folder. That is the real folder on the disk, for example C:\Users\YourName\Documents\SharedProject. It is not the \\ path. The \\ path is how other computers see this same folder.
  2. Put the file in that folder. You can drag it in from the desktop, or use File, Save as, and choose this folder. The file name can have spaces. Example: save notes.txt directly inside SharedProject, not inside a different folder.
  3. On the other computer, finish section 7 so Team Code Link has joined. Look at Source on the top bar and copy the whole path, including the two backslashes at the start.
  4. On that other computer, open File Explorer. That is the yellow folder icon. Click the long address box at the top, paste the path, and press Enter.
  5. You should see notes.txt. Double-click it to open it. To edit it in Cursor, in Cursor choose File, Open Folder, and paste that same \\ path.

The other person should see the file without you emailing it. If you add a second file to the host folder, it appears in the same File Explorer window after a refresh. Press F5 in that window to refresh.

If File Explorer says it cannot find the path, check that the host is on, Tailscale is connected on both sides, and Team Code Link on the host was started with Run as administrator. If Windows asks for a username and password, the share did not get created. On the host, close Team Code Link, start it again with Run as administrator, and click Host and share. The file still has to be inside the chosen folder, not only on the desktop.

One person should edit a given file at a time. If a Cursor agent already holds the file, another Cursor agent’s save is refused. Saving from Notepad or another editor is not refused. The host computer must stay on. Closing the host, or disconnecting Tailscale, hides the folder from everyone else.

Share a file through GitHub

GitHub is a website that stores a project. A repository is one project on that website. A commit is a saved snapshot of the files, with a sentence that says what changed. Push means send that snapshot from your computer up to GitHub. Pull means download the latest snapshot from GitHub onto a computer.

Team Code Link’s GitHub choice copies a repository down into the folder the first time the folder has no project history. It does not send later files up by itself. The steps below are how you send a file up, and how the other person gets it.

  1. On the host, create a GitHub account at https://github.com/signup if you do not have one. Sign in.
  2. Click the plus sign in the top right of GitHub, then New repository. Name it with letters, numbers, and hyphens, such as shared-project. Choose Private if only invited people should see it. Leave “Add a README” turned off if the folder on your computer already has files. Click Create repository.
  3. On that new repository page, click Settings, then Collaborators, and invite the other person by their GitHub username. They must accept the invite. A private repository is invisible to them until they accept.
  4. Copy the repository address from the green Code button. It looks like https://github.com/yourname/shared-project. Copy the HTTPS address, not the SSH one.
  5. In Team Code Link on the host, set Project lives to In a GitHub repo, copied into a folder here. Paste that address into GitHub repo. Click Choose folder and pick an empty folder. Run the program as administrator and click Host and share. If the folder does not already contain a hidden .git folder, the program downloads the repository into it. An empty new repository downloads as an empty folder, which is fine.
  6. Put the file you want to share into that folder, the same way as the Tailscale steps. Example: notes.txt inside the folder.
  7. Git must be installed (section 4). Open PowerShell. Go to the project folder and send the file to GitHub. Replace the folder and write a real sentence after -m:
cd C:\Users\YourName\Documents\SharedProject
git init
git add notes.txt
git commit -m "Add notes.txt."
git branch -M main
git remote add origin https://github.com/yourname/shared-project.git
git push -u origin main

git init starts history in this folder. Skip that line if the folder was already copied from GitHub and git status works. git add notes.txt chooses that one file. git commit saves the snapshot on this computer. git remote add origin tells Git which GitHub address to use. Skip that line if it says the remote already exists. git push sends the snapshot to GitHub. The first push opens a browser window so you can sign in to GitHub. Finish that sign-in. When the command ends without an error, open the repository page in a browser and you should see notes.txt.

  1. On the other computer, install Git the same way. Open PowerShell and download the project. Pick an empty folder name at the end:
cd C:\Users\TheirName\Documents
git clone https://github.com/yourname/shared-project.git SharedProject

git clone creates SharedProject and puts notes.txt inside it. They can also set Team Code Link’s Project lives to the GitHub option, paste the same address, choose an empty folder, and click Join. That copies the repository once.

  1. The next time the host adds or changes a file, send only the new snapshot. From the project folder:
git add notes.txt
git commit -m "Update notes.txt."
git push

On the other computer, open PowerShell in their copy of the folder and download that snapshot:

cd C:\Users\TheirName\Documents\SharedProject
git pull

git pull brings in what was pushed. Their notes.txt then matches the host’s saved snapshot. It does not update by itself. They run git pull when they want the new copy.

Do not commit passwords, the room code, or a file named .team-link-client.json. That file is how this computer signs into the room. It should stay on the computer. If git status lists it, do not git add it.

Tailscale shows the file as soon as it is saved in the host folder, while the host is on. GitHub shows the file after a successful push, and the other person sees it after clone or pull, even if the host is later turned off.

11. Skills, settings, and leaving

Skills. Open the Skills tab on each computer before you connect. The list is discovered on that computer. It is not typed in. Uncheck a skill to keep this agent from bringing it. Then click Connect, or Host and share, again so the room receives the new list.

Settings. The Settings tab stores the computer name, agent name, project, folder, and whether this PC hosts or joins. Save writes that down for the next time you open the window. Save does not enter the room. Host and share, Join, and Connect do.

Leaving. A seat stays in the room until that agent leaves or someone removes it. Closing a laptop lid does not remove the seat. There is no timer that drops a quiet person. On the older room board, a signed-in conductor can remove a seat. The room code alone cannot remove anyone.

13. What this program does not do yet

  • It does not connect the Cursor chat that is already open. Connect starts a separate Cursor agent program.
  • That program runs one turn and exits. It does not sit in the room forever. Another turn starts when you click Connect again, or when the conductor sends new instructions to a seat that is already on an active part.
  • The window cannot publish the plan by itself. Section 9 is the way to publish it.
  • The window cannot mark a part finished or merge the parts back into one branch. Those actions exist in the older room tools. Finishing a part is workspace.py finish. Closing a part for everyone on it is workspace.py complete --task t1, run the same way as the plan command, from the project folder.
  • A person saving outside Cursor is not blocked by the file lock.
  • An agent name other than cursor connects only when a program with that exact name is installed. Only Cursor is wired to the room tools by the Connect button.
  • Choosing GitHub in the window copies the repository into the folder once. It does not push later files. Section 10 is how you send those files up with git push, and how the other person downloads them with git pull.
  • GitHub does not contain Team Code Link.exe. The other computers need the file from section 4, then sections 3, 7, and 8 on their own PC.

Host first. Confirm the four items on the top bar. Then have each other person join with the code, then connect their own agent.
